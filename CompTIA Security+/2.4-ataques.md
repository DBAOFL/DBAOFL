# Ataques Físicos
Se o invasor conseguir encostar fisicamente no hardware, a segurança lógica deixa de existir. O Professor Messer divide a segurança física em perímetros e controles de acesso:
- Vulnerabilidades de Acesso: Sem barreiras, um invasor pode inserir um pendrive malicioso (USB drop), furtar discos rígidos, instalar um gravador de digitação físico (keylogger) ou reiniciar o servidor em modo de recuperação para apagar as senhas administrativas.

        Controle de Perímetro: Uso de cartões de acesso (badge access) com leitores RFID/NFC em todas as portas internas e externas.

        Mantraps (Eclusas): Áreas com duas portas onde a segunda só abre quando a primeira fecha, impedindo o tailgating (carona física).

        MFA Físico: Exigir o cartão de acesso combinando-o com biometria ou PIN nos pontos de entrada das salas de servidores.

2. Ataques de Rede e Acesso
DoS (Denial of Service) e DDoS

    DoS: O atacante usa uma única conexão para sobrecarregar os recursos de um serviço (largura de banda, CPU ou memória) até que ele pare de responder aos usuários legítimos.

    DDoS (Distributed DoS): O ataque é amplificado utilizando uma Botnet (uma rede de computadores infectados controlados pelo atacante, chamados de zombies).

    Diferencial do Messer: Ele destaca os ataques de Amplificação (onde o invasor envia requisições pequenas com IP falsificado para servidores públicos, como DNS ou NTP, que respondem com pacotes gigantescos direcionados à vítima).

Ataque por DNS (Domain Name System)

    DNS Spoofing / Cache Poisoning: O invasor altera a tabela de resolução de nomes de um servidor DNS, inserindo um endereço IP falso para um domínio legítimo. Quando o usuário tenta acessar banco.com.br, o DNS envenenado o envia para o IP do servidor do hacker.

    Domain Hijacking: O atacante consegue acesso à conta do registrador do domínio (ex: GoDaddy) e altera diretamente as configurações do DNS para apontar para seu próprio servidor.

Ataque por Wireless (Sem Fio)

    Rogue Access Point: Um ponto de acesso sem fio instalado na rede corporativa sem a autorização do administrador (geralmente por um funcionário descuidado ou invasor infiltrado), abrindo uma brecha de segurança na rede física.

    Evil Twin: Um ponto de acesso configurado pelo invasor com o mesmo SSID (nome) e configurações de segurança de uma rede legítima de um local (ex: Wi-Fi do aeroporto). Os dispositivos das vítimas conectam-se a ele achando que é a rede real.

    Diferencial do Messer: Ele frisa a importância do protocolo 802.1X para impedir que Rogue APs consigam obter endereços IP na rede cabeada.

Ataque On-Path (Anteriormente Man-in-the-Middle)

    Definição: O invasor se posiciona silenciosamente no fluxo de comunicação entre dois dispositivos (ex: entre o seu celular e o gateway de internet).

    Como é feito na rede local (LAN): Através de ARP Poisoning (envenenamento de ARP), onde o invasor envia mensagens ARP falsas para associar o seu próprio endereço MAC ao endereço IP do roteador legítimo.

    Resultado: Todo o tráfego da vítima passa pelo computador do invasor antes de ir para a internet, permitindo interceptação e modificação de dados em tempo real.

Ataque de Replay (Reenvio)

    Definição: O atacante intercepta um pacote de dados legítimo trafegando pela rede (como um hash de senha ou um token de autenticação) e, sem precisar descriptografá-lo, reenvia o pacote exato mais tarde para se autenticar no sistema se passando pela vítima.

    Prevenção segundo o Messer: Uso de criptografia com carimbos de data/hora (timestamps), números de sequência descartáveis (nonces) ou protocolos de autenticação dinâmica (como Kerberos).

3. Código Malicioso (Malicious Code / Malware)

O Professor Messer ensina a categorizar os tipos de malware pelo seu comportamento e método de propagação:

    Vírus: Código malicioso que requer ação humana para ser executado e se propagar. Ele se anexa a um arquivo hospedeiro (como uma planilha ou um executável).

    Worm (Verme): Malware autônomo que não precisa de interação humana nem de um arquivo hospedeiro. Ele se replica sozinho explorando vulnerabilidades de rede de computador em computador.

    Trojan (Cavalo de Troia): Software malicioso disfarçado de programa legítimo e útil. O usuário o instala voluntariamente, mas ele executa atividades nocivas ocultas (como instalar um backdoor).

    Ransomware: Criptografa os dados locais do usuário e exige pagamento (geralmente via criptomoedas) para liberar a chave de descriptografia. Messer ressalta que a única defesa 100% eficaz contra isso é ter um sistema de backup offline.

4. Ataques a Aplicações (Application Attacks)
Injection (Injeção)

    SQL Injection (SQLi): Entrada de comandos SQL em campos de texto de formulários que não possuem validação. O comando inserido altera a consulta que vai para o banco de dados, permitindo extrair credenciais ou tabelas inteiras.

    Cross-Site Scripting (XSS): Injeção de scripts (HTML/JavaScript) em páginas web.

        XSS Não-Persistente (Reflected): O script é enviado em um link malicioso e executado imediatamente no navegador do usuário que clica nele.

        XSS Persistente (Stored): O script é salvo diretamente no banco de dados do site (como na área de comentários) e infecta qualquer um que abrir a página.

Buffer Overflow (Estouro de Buffer)

    Definição: Ocorre quando uma entrada de dados é maior do que o tamanho alocado para ela na memória RAM (o buffer). Os dados excedentes transbordam e sobrescrevem as instruções que estavam nas áreas de memória adjacentes.

    Consequência: Pode causar o travamento do sistema ou permitir ao invasor injetar códigos diretamente no ponteiro de instruções do processador para executar códigos com privilégios de sistema.

Privilege Escalation (Escalação de Privilégios)

    Horizontal: O atacante ganha acesso a recursos de outro usuário que possui o mesmo nível de privilégios que ele (ex: acessar a conta de outro cliente).

    Vertical (Root/Admin): O atacante explora uma falha de sistema para elevar seus privilégios de usuário comum para administrador, obtendo controle total da máquina.

Cross-Site Request Forgery (CSRF / XSRF)

    Definição: O ataque utiliza as credenciais e a sessão ativa que a vítima já possui em um site para realizar ações não autorizadas em seu nome.

    Mecanismo: A vítima clica em um link malicioso enquanto está logada em sua conta bancária. O link envia uma requisição de transferência para o banco; como o navegador da vítima já possui os cookies de login ativos, o banco processa a transação achando que ela foi solicitada intencionalmente pelo usuário.

5. Ataques Criptográficos (Cryptographic Attacks)

    Ataque de Colisão (Collision Attack / Birthday Attack): Baseado no paradoxo do aniversário. O objetivo é encontrar duas mensagens de entrada diferentes que resultem no mesmo hash de saída. Se o invasor conseguir gerar essa colisão, ele pode substituir um arquivo legítimo assinado digitalmente por um arquivo malicioso com a assinatura idêntica.

    Downgrade Attack: O invasor intercepta a fase de negociação de conexão de segurança entre um cliente e um servidor e os força a usar um padrão criptográfico mais antigo e sabidamente vulnerável (como forçar TLS 1.3 a recuar para SSL 3.0) para depois quebrar a criptografia fraca.

6. Ataques de Senha (Password Attacks)

    Força Bruta (Brute Force): Tentativa exaustiva e matemática de testar todas as combinações possíveis de letras, números e caracteres especiais até descobrir a senha. Pode ser feito de forma offline (tentando quebrar um arquivo de hashes roubado) ou online (testando direto no portal de login).

    Ataque de Dicionário (Dictionary Attack): O atacante utiliza listas pré-definidas de palavras conhecidas, senhas comuns vazadas na internet e substituições comuns (como usar @ no lugar de a). É muito mais rápido do que a força bruta convencional.

    Password Spraying: Tentativa de testar pouquíssimas senhas muito comuns (ex: Senha123, Password1) contra milhares de contas de usuários diferentes.

        Diferencial do Messer: Ele ressalta que o Password Spraying é usado especificamente para contornar políticas de bloqueio de conta por tentativas frustradas de login (Account Lockout), já que cada conta só recebe uma tentativa de login incorreta.
